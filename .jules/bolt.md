
## 2026-07-07 - [JS Map as LRU Cache]
**Learning:** For interactive UI components that perform heavy repetitive math (like the 61-day timeline scrubber triggering `calculateTransits` inside `src/lib/astrology.ts`), relying solely on React `useEffect` debouncing is insufficient because multiple scrubber ticks re-evaluate the same sequence of dates rapidly. A vanilla `Map` handles LRU cleanly and quickly by combining `delete` and `set` on access to push the most recently used items to the end of its iteration order, turning O(ms) calculations into ~0ms.
**Action:** When implementing heavy computational logic bound to dynamic scrubber inputs, apply an internal LRU cache via `Map` directly on the utility side rather than just throttling the UI/React side.
## 2024-06-25 - [Constant Re-allocation Bottleneck]
**Learning:** Re-allocating static configuration objects and arrays on every function call within hot loops (e.g., `calculateAshtakavarga`, `checkVedha`) can dramatically slow down heavy iterative logic like a 61-day timeline calculation, causing significant GC pressure and wasted CPU cycles. Even for small objects, hoisting them to module scope can result in >10x micro-benchmark improvements in execution time for those specific operations.
**Action:** Always inspect frequently called utility functions for internal constant object/array declarations. Move immutable configuration mappings, rules sets, and static lookups to the module/global scope.
## 2026-07-08 - [Ashtakavarga Calculation Bottleneck]
**Learning:** In highly iterative contexts like the interactive 61-day scrubber timeline, `calculateAshtakavarga` was doing heavy object allocation (`new Array(12).fill(0)`) and performing multi-level nested loops inside dynamically scoped lookups. By extracting the fixed astrological rules into flat precomputed bitmasks (`Int32Array`) at module scope, allocating objects once per run, and replacing nested loop searches with bitwise checks (`rule & (1 << offset)`), `calculateAshtakavarga` runtime improved by ~20x. Additionally, modifying `checkVedha` to use a standard `for` loop instead of `Array.prototype.find` yielded another measurable speedup by avoiding creating an arrow function closure each time.
**Action:** When working with nested array rules and mapping operations in hot paths, flatten the nested loops into bitmask lookups, avoid inner loop closures like `.find()` or `.forEach()`, and aggressively pre-allocate objects and maps outside function scope or loops where applicable.
